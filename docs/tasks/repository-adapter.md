# Repository runner implementation contract

Implement the four modules below using TypeScript/ESM, explicit `.ts` imports and Node built-ins only. Shared types are fixed in `src/repo-types.ts`; do not change them or the tests. Reuse the existing `runSwarm`, kernel and `TokenBudget`. No independent agent scheduler, direct production model calls in tests, or weakening of acceptance.

## `src/repo-manifest.ts`

Export `safeRepoPath(value: unknown): string` and `parseRepoTask(value: unknown): RepoTask`.

Strict task schema: `{version:1, goal:string, files:[{path,instructions,dependsOn?:string[],checks?:[{argv:string[],timeoutMs?:number}]}], context?:string[], protected:string[], checks:[{argv:string[],timeoutMs?:number}]}`. Reject unknown keys at every level, wrong types, blank goal/instructions/argv[0], duplicate targets, no files, no final checks or protected files, duplicate path lists, protected/target overlap, self/unknown target dependencies and cycles. A path may appear in context as well as protected or targets. Default context, dependsOn and local checks to []; command timeout to 30000 ms; explicit timeouts are integers 1..300000. Max 64 targets, 256 context/protected paths, 32 commands per list; strings must be bounded (goal/instructions <=32000 chars, path <=1024, each argv <=4096, <=128 args). Reject `__proto__` own unknown keys. Return freshly allocated normalized data, do not mutate input.

Paths are nonempty repository-relative POSIX paths. Reject absolute paths, backslashes, control characters, empty/dot/dotdot components, any `.git`, `.sheep`, `node_modules` component, any `.env` or `.env.*` basename and `.sheep-internal` component (reserved host artifacts). Do not normalize traversal into an allowed path. Allow spaces and Unicode.

## `src/repo-files.ts`

Export `captureRepository(repository:string, task:RepoTask): Promise<RepoSnapshot>`, `materializeRepository(snapshot:RepoSnapshot, directory:string, contents:Readonly<Record<string,string>>):Promise<void>`, `applyRepository(snapshot:RepoSnapshot, contents:Readonly<Record<string,string>>):Promise<string[]>`.

Capture a real Git worktree root (resolve via realpath + git rev-parse --show-toplevel, accept a subdirectory by resolving to root). Read working bytes, not HEAD blobs: preserve existing tracked modifications and tracked deletions. Include regular tracked files plus explicitly named existing context/protected/target files; unrelated untracked files stay out. Exclude `.git`, `.sheep`, `.env*`, `node_modules` by component. Reject symlinks (including any parent component), submodule entries and nonregular files rather than dereference them. Context/protected must exist; writable targets may be new (initial content empty, no original entry). Capture HEAD. Initial target/context text must be strict UTF-8, no NUL, max 2 MiB each. Other tracked files may be binary and are copied byte-preserving. Bound snapshot to 10000 files and 128 MiB total. Handle unusual tracked names with NUL-delimited git output. Preserve executable bits.

Materialize only into a fresh directory (fail on existing path); copy the snapshot, then overlay only declared target contents. Reject unknown overlay paths, nonstring or non-UTF8/NUL or >2 MiB target content. Do not copy `.git`, use symlinks, mutate snapshot buffers or the source. New nested target directories are supported. Overlay may be partial.

Apply only declared target contents. Before writing anything, recheck HEAD, all captured entries (bytes/modes/path type), captured tracked path/deletion set, and every originally absent target. Refuse tracked/context/protected edits, new target collisions, symlink substitution, or any drift since capture; preserve unrelated untracked work. Validate all paths and overlay values before writes. Stage replacements before applying; preserve modes; on a write failure restore previously applied bytes/remove newly created files (record/throw if rollback fails). Never overwrite existing symlinks. Return only changed target paths, skip unchanged targets. This is drift protection for a single operator, not an OS transaction or adversarial concurrent filesystem guarantee.

## `src/repo-checks.ts`

Export `runRepoChecks(snapshot:RepoSnapshot, contents:Readonly<Record<string,string>>, commands:readonly RepoCommand[], outputRoot:string):Promise<RepoVerification>`.

Create a unique fresh candidate directory beneath outputRoot using materializeRepository. Run supplied argv arrays sequentially in candidate cwd without a shell, with each configured timeout. Do not invent npm install or rewrite commands. Capture stdout/stderr bounded to 65536 bytes per stream, record exitCode/signal/timedOut/durationMs; spawn failures are failed checks, not passes. On timeout terminate the process group (POSIX detached child), then kill remaining group processes even if the leader exits; reap the leader. Use a minimal child environment (PATH, optional SystemRoot/WINDIR; HOME/TMPDIR under candidate scratch), never forward provider/API/auth env values. Candidate code/checks run as trusted host subprocesses, not a security sandbox.

Compare every materialized snapshot/target file after commands to its expected bytes/type/mode; any tracked/target/protected mutation/deletion/symlink is a failure even on exit 0. Generated extra files such as build outputs may remain in the candidate but are not adopted. Preserve candidate and check logs as evidence. Skip later commands after a failing command. Return ok only with all commands passed and original candidate inputs unchanged. Empty commands are allowed for structural-only local validation.

## `src/repo-run.ts`

Export `runRepository(options:RepoRunOptions, caller?:RepoCaller):Promise<RepoRunReport>`.

Validate manifest, runtime selection, all numeric limits, output path and capture before model calls. Support tool-less codex/deepseek/opencode-go; reject docker-agent for this host-check runner (no false isolation claim). Defaults: codex/Luna, upper Codex/Astra; N4/C2, maxCalls16, maxMetaCalls2, rounds12, call timeout120000, output tokens16000, total tokens300000, reservation30000. Respect supplied model/runtime including Go deepseek-flash. Reject invalid counts before any paid call. Output root must be new; never overwrite prior evidence. Use inner `outputRoot/swarm` for runSwarm and `outputRoot/checks` for candidate checks.

Create a host-owned SwarmTask/CodeFixture using only selected targets/context and two reserved `.sheep-internal/` goal/guidance artifacts. Immutable goal/manifest in source artifact; mutable upper guidance in spec artifact cannot replace fixed oracle. Trigger all targets via source version change. Include each declared target dependency, read-only context dependencies, and guidance dependencies. Dependencies refer to target artifacts as-is so existing scheduler orders them. `verify` preserves immutable artifacts and nonempty guidance; local scopes call only each target's local checks (or structural-only checks), final scope runs all final checks against combined candidate. Return failed verdicts on check errors; never allow generated code to modify acceptance definition. Only selected files are sent to models; the full snapshot is only for host verification.

Wrap each caller with shared TokenBudget reservation/settlement, route by worker/meta role from sessionId (not model-name equality). Use provided injected caller when supplied, otherwise callerForRuntime for each role. Save budget evidence after each call including failed/unknown receipts; unknown usage or overrun stops new provider admissions. Retain original receipt error facts. Do not call models on reserve denial. No budget bypass with simultaneous calls. Count upper use too. runSwarm handles kernel completeness; repository success additionally requires settled known usage, no budget excess/denial, final checks pass.

Read accepted contents from inner artifacts.json; export selected target content to outer artifacts.json, changed paths and original hashes to changes.json, normalized task.json, budget.json and result.json (RepoRunReport). Keep failed outputs as failure evidence. On success and apply:true invoke drift-checked applyRepository; drift/apply errors make outer report unsuccessful and applied:false, preserving candidate and failure reason. Default apply:false keeps source unchanged. No automatic whole-run retry or final-oracle weakening. Report the actual repository task rather than claim the built-in measurement fixture was run.
