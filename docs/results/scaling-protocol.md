# 初期の規模比較の条件

2026-09-10 JST。M3の探索的実験。開始済みの16体pilotと同じruntimeファイルを `.sheep/scale-source-v1/` へ複製し、実験中の開発変更が混ざらないようにした。`source-manifest.json` のSHA256を開始時に検査し、各runの結果にもハッシュを記録する。

下位は `gpt-5.6-luna`、上位は `gpt-6-astra`。各個体は過去4件までの局所作業記憶を持つ。担当は未稼働の個体のうち割当回数の少ないものを優先し、同数なら過去の読取先と作業近傍の重なりで選ぶ。この担当規則はhostの実装であり、役割の創発を仮定しない。

## 比較系列

| 系列 | 個体数N | 最大同時数C | consumer数 | 反復数 |
|:---|:---|:---|:---|:---|
| 同じ仕事量 | 8 / 16 / 32 | N | 32 | 各2 |
| 人数に比例する仕事量 | 8 / 16 / 32 | N | 2N | 各2 |
| 誤った共有指示 | 8 / 16 / 32 | N | 32 | 各1 |
| 同時数を固定 | 8 / 16 / 32 | 8 | 32 | 各1以上 |

consumer4個につきreport1個を追加し、reportは離れたconsumerを参照する。consumer32なら修正対象は計40個。16体/consumer32は最初の二系列の共通点であり、独立した試行として二重計上しない。同時数固定のN8は同じ仕事量系列のN8を共用する。

最初のpilotは下位64呼出し・12roundの上限、続く実験は下位3×consumer数・20roundの上限。上位はいずれも最大2呼出し、1呼出しのtimeoutは90秒。この差を揃えるため同じ上限のN16条件を追加実行し、最初のpilotを主比較から外して併記した。主比較15runと別pilot1runである。規模比較は共通の総費用上限を競うM5とは分ける。

誤指示条件は小数の出力を切り捨てる誤った共有仕様を入れる。各waveの終了時、未解決の失敗が2件以上増えた場合などに上位を起動する。上位は失敗履歴と現在の共有仕様/APIを読み、仕様だけを変更できる。外側の受入は変えられない。下位から上位への相談はない。

## 記録と判定

成功は全体の固定oracleによる実Node受入と、kernelの未処理義務・未配送通知・blocking claim等が残らないことの両方で判定する。モデルの自己申告は採点に使わない。使用量不明の呼出しはゼロと同一視せず別に数える。

個体数、最大同時数、実稼働、割当分布、私有記憶を再利用した呼出し数、局所受入の失敗、上位呼出し/介入、上下の入力/出力token、モデル応答時間、確定待ちを記録する。tokenにはCLI側の付帯contextも含まれる。通貨換算は行わない。

`scripts/scale-experiment.mjs` は各runを順次実行し、失敗も残して次へ進む。`scripts/summarize-scales.mjs` は保存した結果のハッシュを確認し、成功だけを抽出せず集計する。

## 解釈の限界

通常条件は各2回、誤指示と同時数固定の追加対照は各1回の初期観測である。モデル/providerの時間変動、ネットワーク、同じ端末上の開発や検証作業を統制した性能benchmarkではない。統計的な優位や最適人数を断定しない。

固定された既知依存の合成taskである。個体数と同時数が同時に変わる系列の短縮を、個体間の創発に帰属しない。私有記憶や近傍選択を外した対照は今回の系列に含めていないため、それぞれ単独の寄与も未測定。M5の別task比較も一般repositoryでの有用性を証明するものではない。
