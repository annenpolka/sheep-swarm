## Method and evidence boundary

Each scenario is performed by a new Luna executor with no conversation history, using the skill and the scenario contract. A executes the actual Codex/Luna CLI. B reads a real durable-run output generated by an injected unknown-usage response; B is not a live Go trial. The parent verifies saved outputs rather than accepting self-report alone.

`collaboration.spawn_agent` returns no canonical `tool_uses` / `duration_ms` fields. These are recorded as N/A rather than approximated as official measurements. Provider call count, retries and run duration are separate evidence. Full numeric convergence cannot be claimed without those fields.

## Failure pattern ledger

- **Enclosing sandbox blocks a nested CLI's state initialization**
  - Example: iteration 1 A produced four `nonzero-exit` receipts, all without model events; Codex could not write `state_5.sqlite` or initialize its app-server.
  - General Fix Rule: Document a nested tool's host prerequisites at the execution step; use a narrowly scoped execution permission for already-authorized commands while preserving the inner sandbox and bounds.
  - Seen in: iteration 1 A.
  - Existing text handled failure honestly but did not describe the enclosing permission requirement.
- **Treating resume as read-only evidence inspection**
  - Example: iteration 1 B invoked `--resume` on an already locked run; SQLite bytes changed, and the executor attempted to restore its logical payload.
  - General Fix Rule: Determine terminal/locked status from saved evidence before any mutating resume; never repair forensic evidence after a probe.
  - Seen in: iterations 1 B, 2 B.
  - Existing text said to inspect first and preserve evidence, but placed the runnable resume example before a concrete no-resume rule. Deferred to the next single-theme patch after the already-selected execution prerequisite.
- **Applying an adapter marker uniformly across runtimes**
  - Example: iterations 2 and 3 A reported Codex usage completeness unavailable because `usageCompleteness` was null, despite successful terminal events and a single counted final usage row.
  - General Fix Rule: Interpret absent metadata through the runtime's actual receipt contract; keep model identity independent of token accounting.
  - Seen in: iterations 2 A, 3 A.

## Hold-out dispatch

The unused Go scenario is therefore dispatched to a new ephemeral Codex/Luna process with only the skill and frozen scenario paths, no author conversation and no prior evaluation reports. It is an independent executing model, not an author self-review; the dispatch mechanism differs from the in-process subagent API and cannot supply its canonical usage metadata.

An initial dispatcher invocation used incompatible sandbox/approve-for-me flags and exited in argument parsing before model output. Its files are retained under `.sheep/skill-eval/dispatch-argument-error-*`. The corrected invocation uses `--approve-for-me` (workspace-write with automatic approval review), preserving the task's execution boundary.
